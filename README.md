# giga-school.com

小学校の教員（GIGAyama）がつくった Web アプリの公開サイトです。
このリポジトリは、独自ドメイン `giga-school.com` のルートを配信します。

- 公開 URL：<https://giga-school.com/>
- 各アプリ：`アプリ名.giga-school.com`（それぞれ別のリポジトリで配信）

## 役割

1. **公開中のアプリへの入口**（Web アプリ 38 本、Chrome 拡張機能・ツール 3 本）
2. **サイトの所有権確認**
   Google Search Console の HTML ファイル確認用ファイルをルートに置いています。
   OAuth 同意画面（Google Auth Platform）の審査では、ホームページ URL のオリジンについて
   所有権の確認が必要になります。各アプリはサブドメインで配信されるため、
   オリジンのルートを配信するこのリポジトリがないと、ルートでの所有権確認ができません。

> [!IMPORTANT]
> `google*.html` は Search Console の確認ファイルです。**削除すると所有権の確認が外れ、
> OAuth 審査が差し戻される**ことがあります。移動・改名しないでください。

> [!NOTE]
> `sitemap.xml` には各アプリのサブドメインも並べています。別のホストの URL を
> 1 つのサイトマップに書けるのは、Search Console で `giga-school.com` を
> **ドメイン プロパティ**（DNS の TXT レコードで確認するもの）として登録し、
> サブドメインまで所有権が確認できている場合です。`https://giga-school.com/` の
> URL プレフィックス プロパティしかないと、サブドメインの行は無視されます。

## 構成

```
index.html            トップページ（カードはすべて HTML に直接書いてある）
404.html              見つからないページ
site.webmanifest      PWA マニフェスト
robots.txt            クロールの許可と sitemap の在りか
sitemap.xml           トップページ・紹介ページ・各アプリのサブドメイン（tools/sync-updates.mjs が書き出す）
feed.xml              更新を追うための Atom フィード（tools/sync-updates.mjs が書き出す）
apps/index.html       紹介ページの一覧（tools/sync-updates.mjs が書き出す）
press/index.html      掲載用の資料（tools/sync-updates.mjs が書き出す）
profile/index.html    自己紹介（手で書く。トップページに簡易版の #profile がある）
apps/<slug>/          アプリの紹介ページ（tools/build-articles.mjs が書き出す）
assets/
  style.css           スタイル（@layer で reset → tokens → base → layout → components → utilities）
  app.js              検索・カテゴリ絞り込み・並び替え・テーマ切り替え
  logo.svg            ロゴマーク（配布用。ページ内では色を変えるため直接埋め込んでいる）
  favicon.svg         ファビコン
  apple-touch-icon.png / icon-512.png
  og.png              OGP 画像（1200×630）
  og-profile.jpg      自己紹介ページの OGP 画像（1200×630）
  profile.webp / profile-sm.webp   似顔絵（512／256、円に切り抜いた WebP）
  thumbs/<サブドメイン>-1..6.webp   カードの中で切り替わる画面写真（640×400、WebP）
sw.js                 オフラインでも開けるようにする仕組み（Service Worker）
data/apps.json        掲載しているものの一覧と、公開日・最終更新日
data/articles.json    紹介ページの一覧（tools/build-articles.mjs が書き出す）
tools/sync-updates.mjs  日付を GitHub から取り直し、「更新情報」「紹介ページの一覧」「sitemap.xml」を組み直す
tools/build-articles.mjs  各アプリの note 記事から紹介ページを組み直す
tools/check-404-redirect.mjs  旧アドレスの受け皿が壊れていないか調べる
tools/check-cards.mjs  カードの data-slug・件数・本数が、data/ の数と食い違っていないか調べる
tools/set-topics.mjs  各リポジトリの GitHub トピックをまとめて付け直す（手で走らせる）
tools/set-homepage.mjs  各リポジトリの homepage 欄を新アドレスへ揃える（手で走らせる）
tools/lib/            上のものが使う部品（Markdown の変換・ページの雛形・カテゴリの表）
.github/workflows/sync-updates.yml  それを毎朝走らせる設定
```

**閲覧する側にビルドは要りません。** HTML・CSS・JavaScript をそのまま配信します。
`tools/` は「更新情報」と紹介ページを書き直すためだけのもので、GitHub Actions が動かします。

## サイトから外したいとき

載せたくないアプリは、`data/apps.json` のその項目に `"hidden": true` を足します。

```json
{
  "repo": "Reversi",
  "name": "リバーシ",
  "slug": "reversi",
  "hidden": true
}
```

これで次の朝から、次のものから外れます。

- 紹介ページ（`apps/<slug>/`）と、カードの「紹介を読む」
- `sitemap.xml`
- トップページの「更新情報」と、「公開中のアプリ」の件数

**カードは手で外してください。** サムネイルもキーワードも入っている手書きの
HTML なので、機械が削ると戻すときに書き直すことになります。外し忘れは
`node tools/check-404-redirect.mjs` が見つけて止めます。

> [!IMPORTANT]
> **項目そのものは消さないでください。** `data/apps.json` は
> 旧アドレス（`gigayama.github.io/<リポジトリ名>/`）の転送表も兼ねています。
> 消すと、配布済みのプリントや QR コードからの転送が一緒に壊れます。
> `hidden` なら転送は効いたままです。

> [!WARNING]
> **リポジトリを private にして隠すのは勧めません。** 紹介ページは消えますが、
> トップページのカードとサイトマップの URL は残り、死んだリンクになります。
> さらに GitHub Pages は無料プランだと private リポジトリでは公開されないため、
> アプリ自体が開けなくなります（すでに配った QR コードからも）。

## GitHub のトピック

各アプリのリポジトリに付けるトピックを `tools/set-topics.mjs` の表にまとめてあります。
トピックは GitHub の中の検索とトピックページからの入口になります。README をいくら書いても、
トピックが無いと「education を見に来た人」の目には入りません。

```sh
node tools/set-topics.mjs                             何を付けるか見るだけ
node tools/set-topics.mjs --repo Reversi              1 つだけ見る
GITHUB_TOKEN=… node tools/set-topics.mjs --apply      実際に付ける
```

- トークンは **Administration: write**（classic なら `repo`）が要ります。
  引数ではなく環境変数で渡してください（シェルの履歴と `ps` に残るため）
- 毎朝のワークフローでは走らせません。トピックはめったに変えないうえ、
  書き込みの権限が要るためです。手で走らせるものとして置いてあります
- 表は `data/apps.json` と突き合わせます。アプリを増やして表に足し忘れると、
  実行のたびに警告が出ます

> [!IMPORTANT]
> `PUT /topics` は「置き換え」であって「追加」ではありません。
> GitHub の画面から手でトピックを足したときは、先に表へ写してください。
> 写さずに `--apply` すると、手で足したほうが消えます。

### homepage 欄

同じ要領で `tools/set-homepage.mjs` があります。行き先は `data/apps.json` の `slug` から
機械的に決まるので、**こちらは手書きの表がありません。**

```sh
node tools/set-homepage.mjs                             何に直すか見るだけ
node tools/set-homepage.mjs --repo Reversi              1 つだけ見る
GITHUB_TOKEN=… node tools/set-homepage.mjs --apply      実際に直す
```

- 行き先は `https://<slug>.giga-school.com/`。`GIGAyama.github.io` だけ `https://giga-school.com/`
- `app_launcher` と `Blackboard_Timer` は Chrome 拡張機能でサブドメインを持たないため触りません
- `hidden` のものも対象です。サイトから外していても、サブドメイン自体は生きているためです
- 権限はトピックと同じ **Administration: write**。`PATCH` は冪等なので、途中で止まっても
  もう一度まるごと流して構いません

## アプリの紹介ページ

各アプリのリポジトリの `docs/note/*-note-article.md` に置いてある記事を、
`giga-school.com/apps/<slug>/` のページとして毎朝組み直しています。

- **記事は書きかえません。** 見出しと画像の位置をそのまま HTML にするだけです
- **画像は取り込みません。** 32 本ぶんで 707 枚あります。
  アプリのリポジトリに置いたまま、そのアプリのサブドメインから読みます
- カードの「紹介」リンクは `tools/build-articles.mjs` が貼り直します。
  手で書き足すと、アプリが増えたときに片方だけ古くなるためです
- **目次と読むのにかかる時間を、組み立てのときに付けます。** 見出し（`h2`・`h3`）に
  `s-1` `s-1-2` の連番の id を振り、本文の前に折りたたみ式の目次を出します。
  記事は 1 本 7,300 字ほどですが、画面写真が 22 枚入るので、縦に長いページになります。
  節は 8〜10 あって用がそれぞれ違う（導入手順、使い方、メリット）ので、
  跳べるようにしてあります。**記事の書き方は変えません。**
  仕組みは `tools/lib/article-toc.mjs`。見出しが 2 本以下の記事には目次を出しません
- **何の時間に使うアプリかを、題のすぐ下に出します。** 対象学年（`data/apps.json` の
  `grades`）と、教科・分野（同じく `category`）と、つかいかた（トップページのカードの
  `data-use`）をチップにして、押すとトップの同じ分類だけが出ます（学年はまだ押せません）。
  表示名の正本は `tools/lib/categories.mjs` で、index.html の選択肢とずれていないかは
  `node tools/check-cards.mjs` が見ています
- **記事の終わりに、書いた人を出します。** 学校で使うかを決めるときの材料になるのに、
  紹介記事から `/profile/` へのリンクが 1 本もありませんでした
- **狭い画面では「開く」が下に貼り付きます。** `position: sticky` なので、本文を読み終えると
  その位置に収まり、すぐ下の「開く」と二重には見えません。広い画面では出しません
- **記事どうしをつなぎます。** 各記事の終わりに「ほかの紹介」（関連 3 本＋前後の記事）を出します。
  選び方は「同じカテゴリで、公開日が近いもの」。カテゴリに 3 本ないときは（表現・制作は 1 本）、
  ほかのカテゴリから公開日の近い順に足します。**規則だけで決めるので、増えても手作業はありません**
- **og:image は自分のドメインのものだけ**使います。`raw.githubusercontent.com` の画像は
  SNS のクローラが取りに行けないことがあり、ブランチの先頭を指すので壊れやすいためです。
  自前で出せないときは `assets/og.png` に落とします
- 一覧（`giga-school.com/apps/`）は `tools/sync-updates.mjs` が `data/articles.json` と
  `data/apps.json` から書き出します。**`apps/index.html` を手で直しても次の実行で消えます**

> [!IMPORTANT]
> 画像の URL は、そのリポジトリの Pages がどこを配っているかで変わります。
> `docs/CNAME` があれば `/note/images/…`、ルートに `CNAME` があれば `/docs/note/images/…` です。
> 取り違えるとページの画像が 1 枚も出ないので、増やしたときは実際に開いて確かめてください。

## 対象学年（`grades`）

担任が最初に考えるのは「何年生に使えるか」です。教科・分野とつかいかたの 2 軸では、
そこを引けませんでした。`data/apps.json` の `grades` に、児童が使うアプリだけ書きます。

- `[1, 2, 3, 4, 5, 6]` … 使える学年を並べます。続きなら「1〜6年生」、
  飛んでいれば「1・3年生」と出ます（`gradeLabel()`）
- `[]` … **児童が使うものではない**。週案エディタや宿題ポストなど、先生の道具と拡張機能
- **項目そのものを書かない** … まだ決めていない。チップは出ません

「低学年」「中学年」と書かずに数字で持たせているのは、指す範囲が学校によって違うためです。

決まっていないものは `node tools/check-cards.mjs` が毎回名前を出します。
**全部決まったら、トップページの絞り込みに 3 本目の軸として足せます**
（それまで足さないのは、学年で絞ったときに「まだ決めていないアプリ」が消えてしまい、
「1年生向けはこれだけ」という誤った数を見せることになるためです）。

## 導入を決めるための項目（`account` / `storage`）

学校で使うかを決める人が、いちばん先に確かめるのがこの 2 つです。
どちらも紹介記事のどこかには書いてあるのですが、読まないと分かりませんでした。

| 項目 | 値 | 出る言葉 |
|---|---|---|
| `account` | `none` / `google` / `teacher` | アカウント不要／Google アカウントが必要／先生だけ Google アカウント |
| `storage` | `device` / `none` / `google` | 記録は端末の中だけ／記録を残さない／記録は Google に保存 |

**書いていないアプリには付けません。** 推測で「アカウント不要」と出すと、
学校が誤った前提で判断することになります。

> [!IMPORTANT]
> **Google Apps Script で動いているかどうかからは決められません。**
> GAS のウェブアプリでも、公開の設定によってはログインが要りません。
> 実際、パクパクゴブレットとオンライン原稿用紙 Pro は GAS ですが、
> 記事には「アカウントもログインもいりません」と書いてあります。
> 判断のもとは、記事に書いてある事実だけにしてください。

## アプリを追加・変更するとき

`index.html` の該当箇所を直接編集します。

> [!NOTE]
> **カードに出す名前は、リポジトリ名ではなくアプリの正式名称です。**
> （例：`SchoolPlan_Editor` → 「週案エディタ」）
> 出どころは各リポジトリの `<title>` ／ manifest の `name` ／ README の見出し ／
> Google Apps Script の `APP_NAME` です。リポジトリ名でも検索できるよう、
> `data-keywords` の末尾にリポジトリ名を入れてあります。
> 並び順は、この表示名を日本語の照合順（`localeCompare(…, 'ja')`）で並べたものです。

1. **Web アプリ** … `<ul class="cards" id="app-list">` の中に `<li class="card">` を追加します。
   既存のカードをコピーし、次の 5 か所を書き換えてください。
   - `data-cat` … 教科・分野の id（`kokugo` / `sansu` / `tankyu` / `gakkyu` / `koumu` /
     `seisaku` / `game` / `other`）。**1 枚に 1 つだけ**
   - `data-use` … つかいかたの id（下の「絞り込みの 2 本目」を見てください）。
     2 つ持たせるときは空白で区切ります（例：`data-use="shiraberu minna"`）
   - `data-slug` … サブドメインの名前。「最近開いた順」の記録に使うので、
     カードの「開く」の行き先と必ずそろえます
   - `data-name` と `data-keywords` … 検索に使う語。漢字の語は、ひらがなの読みも足しておくと
     児童が探しやすくなります。
   - `style="--cat:…"` と `<span class="tag">` … カテゴリの色と表示名
   - リンク（アプリ本体・プライバシーポリシー・利用規約・GitHub）と、
     コピー・共有ボタン（`.card__acts`）の `data-url` / `data-title`
   - サムネイル … `assets/thumbs/<サブドメイン>-1.webp` 〜 `-6.webp` を置き、
     `<div class="card__media" data-shots="6">` の中の `<img>` をそこへ向けます。
     画像がまだ無いときは
     `<div class="card__media card__media--tile" data-initial="頭文字"></div>`
     に置き換えると、カテゴリ色のタイルが描かれます。
2. **絞り込みの件数** … 教科・分野とつかいかた、**両方の**プルダウンの選択肢
   （`<option value="kokugo">国語・言葉（8）</option>` の数字）と、見出し・ヒーローの本数を
   合わせて直します。`profile/index.html` にも同じ件数と本数があります（`.stats` と `.chip`）。
   トップページの `#profile` にある「いまは ◯ 本」も同じです。
   どこが手で、どこが機械かは「本数の数字はどこから来るか」にまとめてあります。
   数え違いは `node tools/check-cards.mjs` が見つけて止めます（トップと自己紹介ページの両方を見ます）。
3. **Chrome 拡張機能など** … `#tools` の中のカードを同じ要領で編集します。
4. `data/apps.json` にも 1 行足します（`repo` / `name` / `kind` / `slug` / `category`）。
   日付は `node tools/sync-updates.mjs --fetch` で埋まります。
5. `node tools/check-cards.mjs` を走らせて、`data-slug`・`data-use`・件数を確かめます。

### アプリを取り下げるとき

リポジトリを消した場合は、次の 5 か所から外してください。外し忘れると、
カードのリンクが 404 になったり、件数が合わなくなったりします。

1. `index.html` の該当する `<li class="card">`
2. `index.html` の先頭にある構造化データ（`application/ld+json`）の該当項目と `numberOfItems`
3. 本数の表記（ヒーローの「◯本」、見出しの「公開中のアプリ（◯本）」、
   絞り込みの選択肢の件数（教科・分野とつかいかたの両方）、
   `<meta name="description">` と `og:description`）
4. `data/apps.json` の該当項目
5. `profile/index.html` の本数・件数（`.stats` の 3 つと `.chip`、年表の「いま」の行）と、
   トップページ `#profile` の「いまは ◯ 本」

`assets/thumbs/<サブドメイン>-*.webp` も不要なら消します。
毎朝のワークフローは、消えたリポジトリを見つけると
「見つからない（削除された？）」と記録に残しますが、自動では外しません。

## 絞り込みの 2 本目（つかいかた）

カードは 2 つの軸で絞り込めます。**掛け合わせ**で効きます（例：国語・言葉 × みんなでやる）。

| 軸 | 属性 | 何を表すか | 数 |
|---|---|---|---|
| 教科・分野 | `data-cat` | **何の時間に使うか**。1 枚に 1 つだけ | 8 分類 |
| つかいかた | `data-use` | **学びのどの場面を助けるか**。1 枚に 2 つまで | 8 分類 |

教科だけだと、「明日の授業で子どもに何をさせたいか」から探せませんでした。
逆に、つかいかただけだと「国語の時間に使えるもの」が見つかりません。両方を残しています。

つかいかたの id と意味：

| id | 表示 | 入れるもの |
|---|---|---|
| `susumu` | 自分で進める | 見通しを立て、進み具合を自分で確かめられるもの（みらいコンパス など） |
| `renshu` | 練習する | くりかえして身につけるもの（九九カード、かきかたマスター など） |
| `shiraberu` | 調べる | 資料や事象を見て考えるもの（じどう車ずかん など） |
| `tsukuru` | つくる | 作品や成果物を仕上げるもの（オンライン原稿用紙、音楽制作スタジオ など） |
| `furikaeru` | ふりかえる | 記録して見返すもの（ふりかえりジャーナル、どくしょちょきんばこ など） |
| `minna` | みんなでやる | 対戦・協働など、ひとりでは成り立たないもの（人狼ゲーム、みっけ！ など） |
| `sensei` | 先生の仕事 | 準備や校務を軽くするもの（週案エディタ、宿題ポスト など） |
| `hoka` | そのほか | 上のどれでもないもの |

> [!NOTE]
> **2 つ持たせるのは、本当に両方のときだけ**にしてください。
> いまは「みっけ！」（調べる・みんなでやる）と「まなびクエスト」（ふりかえる・自分で進める）の
> 2 枚だけです。迷ったら 1 つにします。多く付けるほど、絞り込みの意味が薄くなります。

URL にも残ります（`/?cat=kokugo&use=minna#apps`）。自己紹介ページからは、この形で
それぞれの分類へリンクしています。

### 見た目は 2 つのプルダウン

はじめは押しボタン（`.chip`）を 2 列に並べていました。**18 個が 1 つの塊に見えて、
どれが何の列なのか分からない**という問題があり、選ぶものは選ぶ形にしました。

- 件数は選択肢の中に入れます（「国語・言葉（8）」）
- 何かで絞っているあいだは、枠に色が付き、「絞り込みを外す」が出ます
- 押しボタンは自己紹介ページの内訳（`/profile/`）に残しています。あちらは
  絞り込む道具ではなく、**どんな分類があるかを見せる一覧**なので、並んでいるほうが読めます

### 画面の上に貼り付く範囲

`.finder`（ことばで探す欄と、絞り込み 2 つ）だけが貼り付きます。
件数の知らせ・「絞り込みを外す」・並び順は、その下の `.finder__foot` に置いてあり、
**貼り付きません**。スクロールすると上へ流れていきます。

貼り付く高さは、そのまま読める面積を削ります。4 行ぶん貼り付けていたときは、
スマホ（390×844）で**画面の 50%** がヘッダーと探し方の欄で埋まり、カードが 1 枚も
入りきりませんでした。いまは 22% です。知らせは絞り込んだ直後に見るもの、
並び順は最初に一度決めるもので、どちらもスクロール中には要りません。

> [!IMPORTANT]
> **`.finder` は節の器（`.wrap`）の直接の子にしてください。** `position: sticky` は
> 親の箱の中でしか効きません。見た目を整えようとして `<div>` で包むと、その入れ物の底で
> 貼り付きが外れ、一覧を見ているあいだは探し方の欄が消えます（実際に一度やりました）。
> 上端は `56px`＝背を低くしたあとのヘッダーのすぐ下です。ヘッダーの高さを変えたら、
> ここも合わせてください。

## サムネイルについて

各カードの画像は、**そのアプリのリポジトリにある実際の画面**です。
多くのリポジトリは `docs/note/images/` に note 記事用のスクリーンショットを持っているので、
そこから選んで 16:10 に切り、640×400 の WebP にして `assets/thumbs/` に置いています。
縦に長い全ページキャプチャは、余白ばかりの帯を避けて中身の詰まった部分を選んでいます。

いまは 34 アプリ × 最大 6 枚、合わせて 200 枚・2.9MB です
（1 枚あたり平均 15KB。必要になってから読み込みます）。

### 共有されたときの絵（`assets/og/`）

紹介ページの `og:image` は、記事の 1 枚目の画面写真です。ただし**自分のドメインから
出せるものに限ります**（SNS のクローラは `raw.githubusercontent.com` を取りに行けない
ことがあるため）。Vite で `dist/` だけを配っているアプリは記事の画像がサブドメインから
読めず、**31 本のうち 11 本**が、中身と関係のないサイト共通の絵で共有されていました。

そこで、**共通の絵に落ちてしまう記事だけ**、カードのサムネイルから 1200×630 の JPEG を
作っています。何本あるかは記事が増えるたびに動くので、数は `--check` が数えます。

```
python3 tools/build-og.py          足りないものだけ作る（Pillow が要ります）
python3 tools/build-og.py --check  足りていないかを見るだけ（Pillow は不要）
```

- **記事の画面写真が使えているものには作りません。** サムネイルは記事の 1 枚目とは
  限らず、途中の画面のこともあります。うまくいっているものを、より弱い絵に
  変えることになるためです
- 文字（アプリ名）は焼き込んでいません。日本語のフォントが要り、
  どれが入っているかは環境によって違うので、作った人によって出来上がりが変わります。
  題と説明は `og:title` / `og:description` で渡ります
- 足りているかは CI（`--check`）が見ます。アプリを増やして共通の絵に落ちたときは、
  そこで気づけます

### カードの中で切り替わる画面写真

1 つのアプリにつき最大 6 枚を `assets/thumbs/<サブドメイン>-1.webp` 〜 `-6.webp` として置き、
カードの中で順に切り替えています。

- 選び方は、そのアプリの note 記事用スクリーンショットを**端から端まで散らして 6 枚**。
  操作の流れがひととおり伝わるようにしています。
- **1 枚目だけ `src`、2 枚目以降は `data-src`** です。そのカードが画面に入ってから読み込むので、
  最初の表示は 1 枚目の 33 枚ぶんで済みます。
- 切り替えは **画面に入っているカードだけ**。ページ全体で時計は 1 本しか持ちません。
- 「動きを減らす」設定のときは 2 枚目以降を読み込まず、1 枚目だけを出します。

差し替えるときは、640×400 の WebP を同じ名前で置き換えてください。
枚数を増やすときは `data-shots` の数と `<img>` の数を合わせます。

### ヒーロー下の帯

`index.html` の `<div class="strip">` に、同じサムネイルから **16 枚**を選んで並べ、
ゆっくり横に流しています。載せる枚数を絞っているのは、最初の画面で読み込む量を
抑えるためです（16 枚で 250KB ほど）。

- 並びは **同じ 16 枚を 2 回**書きます。半分だけ動かして、継ぎ目なく元に戻す仕組みです。
  枚数を変えるときは、前半と後半が同じ並びになるようにしてください。
- 帯は装飾なので `aria-hidden="true"`、`alt=""`、リンクにしていません。
  同じ内容は下の一覧に文字つきで並んでいます。
- マウスを乗せると止まります。OS の「視差効果を減らす／アニメーションを減らす」設定では、
  流さずに並べたまま表示します。

## 更新情報の自動更新

`#updates` の節は、`tools/sync-updates.mjs` が組み立てます。
`index.html` の `<!-- updates:start -->` 〜 `<!-- updates:end -->` の間を書き換えるので、
**この範囲を手で直しても次の実行で消えます。**

```sh
node tools/sync-updates.mjs           # 日付はそのままに、HTML だけ組み直す
node tools/sync-updates.mjs --fetch   # GitHub を見に行って日付を取り直してから組み直す
```

- 日付の出どころは GitHub API です。`updatedAt` は最後に push された日
  （`pushed_at`）、`publishedAt` は最初のコミット日を `data/apps.json` に入れてあります。
- 同じ日にまとめて手を入れることが多いので、「最近手を入れたもの」は**日付ごとに 1 行**に
  まとめています。
- 毎朝 6 時すぎ（日本時間）に GitHub Actions が走り、変わっていたときだけコミットします。
  Actions のページから手で実行することもできます。
- アプリを増やしたときは、`index.html` にカードを足したあと `data/apps.json` にも 1 行足して
  ください（`--fetch` で日付は埋まります）。

## 本数の数字はどこから来るか

「38 本」「32 本」といった数字が、サイトのあちこちに出ます。**機械が数え直す場所と、
手で書く場所が混ざっています。** どちらなのかを知らないまま片方だけ直すと、
同じサイトの中で数が食い違ったまま静かに残ります。

正しい数の出どころは 3 つだけです。

| 数 | 出どころ |
|---|---|
| 公開中のアプリ | `data/apps.json` の `kind: "app"`（`hidden` を除く） |
| 拡張機能・ツール | `data/apps.json` の `kind: "tool"`（`hidden` を除く） |
| 紹介の記事 | `data/articles.json` の項目数 |

### 機械が数え直す場所（手で直しても次の実行で消えます）

- `index.html` のヒーローの `<dl class="stats">`（アプリ・拡張機能）
- `index.html` の `<!-- updates:start -->` 〜 `<!-- updates:end -->` の中
- `/apps/`・`/apps/category/<id>/`・`/press/`・`/filtering/`（まるごと組み直します）

### 手で直す場所

- `index.html` … `<meta name="description">`、`og:description`、構造化データの
  `numberOfItems`、見出し「公開中のアプリ（◯ 本）」、`#profile` の「いまは ◯ 本」
- `profile/index.html` … `.stats` の 3 つ、絞り込みの `.chip` の件数、
  「つくっているもの」の拡張機能の本数、年表の「いま」の行

**手で直す場所は `node tools/check-cards.mjs` が全部数え直して止めます。**
「本数が書いてある」ようにしか見えないので、目では気づけないためです。
2026-08-25 に、紹介記事が 32 本になったのに `/profile/` だけ 31 本のまま残っていたのを
見つけたのが、この検査を足したきっかけです。`/apps/` は機械が書くので 32 本に
変わっており、同じサイトの中で 2 つの数が並んでいました。

年表の**過去の**本数（2025年10月の 10 本、など）は、そのときの事実なので直しません。
検査も見ていません。

### 毎朝の流れに足すとき

`.github/workflows/sync-updates.yml` の「変わっていたらコミットする」に、
**書き出す先をひとつ残らず並べてください。** 並べ忘れたページは、毎朝つくり直されては
毎朝捨てられます。リポジトリには古い数字が残り、しかも検査は組み直したあとの
新しいページを見るので緑のままになります。目でも検査でも気づけない壊れ方です。

## 自己紹介のページ（/profile/）

つくっているのがだれなのかは、学校で使うかどうかを決めるときの材料になります。
そこで、詳しい自己紹介を `profile/index.html` に置き、トップページには
似顔絵と数行だけの簡易版（`#profile`）を出しています。

**このページは手で書きます。** `tools/` は触りません。

- 似顔絵は `assets/profile.webp`（512px）と `assets/profile-sm.webp`（256px）。
  円に切り抜いた透過 WebP なので、明暗どちらのテーマでも縁が出ません。
  差し替えるときは同じ名前・同じ形（正方形・円で切り抜き）で置き換えてください
- 共有されたときの画像は `assets/og-profile.jpg`（1200×630）。SNS のクローラが
  読めるように、WebP ではなく JPEG にしています
- 内訳の件数（`.chip`）と本数（`.stats`）は**手で直します**。トップページの
  絞り込みの選択肢と同じ数です。増減したときの直し方は「アプリを追加・変更するとき」に
  まとめてあります。数え違いは `node tools/check-cards.mjs` が見つけて止めます
- **紹介の記事の本数（`.stats` の 3 つめ）だけは、アプリを増やしたときではなく
  記事が増えたときに動きます。** ここを見落としていたので、`/apps/` が 32 本に
  なっても `/profile/` は 31 本のまま残っていました。いまは検査が止めます
- 「これまで」の年表に書いた過去の本数（2025年10月の 10 本、など）は、
  そのときの事実なので直しません
- 節の見た目（`.profile-section` / `.profile-title`）は掲載用の資料と同じ組み方です。
  どちらも通しでは読まれず、見出しを頼りに拾い読みされるページのためです。
  見出しの規則は `.profile-title, .press-title` と並べて **1 つにまとめてあります**。
  同じ値を二か所に書いていたころは、片方だけ直すと静かに離れていきました
- 節が 8 つあるので、上に**ページ内の行き先**（`.profile-jump`）を置いています。
  行き先は各節の見出しの `id`。節を足したら、ここにも 1 つ足してください

## 掲載用の資料（/press/）

媒体やディレクトリの担当者に向けた素材を `press/index.html` にまとめています。
`tools/sync-updates.mjs` が書き出すので、**手で直しても次の実行で消えます。**

載せているもの：そのまま使える紹介文（一行・短め・本文の 3 種、コピーのボタン付き）、
数字と基本情報、ロゴと画面写真のダウンロード、使ってよい範囲、よくいただく質問、連絡先。

- **本数は `data/apps.json` と `data/articles.json` から数え直します。** 手で書くと
  ここだけ古くなり、媒体に古い数字が載ることになります
- 紹介文の長さ（◯字）も自動で数えます。枠に入るかの判断に使ってもらうためです
- コピーのボタンは `assets/app.js` の `[data-copy]` をそのまま使っています。
  `data-copy` に文字を、`data-copy-label` に知らせの文言を入れます

## 最近の更新（`docs/CHANGELOG.md`）

紹介ページには「2026/08/23 現在」と最終更新の日付を出していますが、
**何が変わったのかは分かりません。** 一度使った先生が「新しくなった」と
気づける材料が、どこにもありませんでした。

アプリのリポジトリに `docs/CHANGELOG.md` を置くと、紹介ページに出ます。

```md
## 2026-08-23
- 写真の上限をなくしました
- 音が出ない端末があったのを直しました

## 2026-06-01
- はじめて公開しました
```

- 新しい日付から **3 つ**まで出します
- **書いたアプリにだけ出ます。** 全部で書く必要はなく、よく使われているものだけで意味があります
- 中身の無い日付（見出しだけ）は出しません

> [!IMPORTANT]
> **コミットの題からは作りません。** はじめは `feat:` `fix:` を自動で拾うつもりでしたが、
> 実際に数えてやめました（2026-08-24）。
>
> | リポジトリ | 直近のコミット |
> |---|---|
> | Typa | 10 件すべてが `chore(gate)` / `chore(drift)` / `chore(sw)` |
> | カベカベ合戦 | 12 件のうち 9 件が同じ。残る 3 件も scope が `gate` / `build` |
> | デジタル新聞社 | ここだけ `feat` が並ぶ（作り直した直後） |
>
> 正本を配る仕組みが、同じコミットを 30 本のリポジトリに撒きます。機械的に出すと、
> 紹介ページに「秘密の直書きの検査を入れる」と並びます。使う先生から見れば、
> アプリは何も変わっていません。**「何が変わったか」は、使う人から見て何が変わったか**で
> あって、リポジトリで何をしたかではありません。分けられるのは書いた本人だけです。

## 分野ごとの入口（`/apps/category/<id>/`）

トップページの絞り込み（`/?cat=kokugo#apps`）は、**JavaScript が動いてはじめて効くうえ、
行き先がトップページ 1 枚**です。「国語 アプリ 小学校」で探している人が着地する場所が
ありませんでした。

`tools/sync-updates.mjs` が 8 分野ぶんを書き出します。**手で直しても次の実行で消えます。**

- 中身は、その分野の**アプリ**（`data/apps.json`）と**紹介記事**（`data/articles.json`）の両方。
  記事が 1 本しかない分野（表現・制作）でも、ページとして成り立つようにするためです
- アプリが 1 本も無い分野は作りません。前に作ってあれば消します
- 紹介の一覧（`/apps/`）の上に、この 8 つへのリンクを並べています。
  **絞り込みではなくページなので、JavaScript が無くても効きます**
- サイトマップにも入ります

つかいかた（`data-use`）のほうは、まだページにしていません。
「ふりかえる アプリ」のような探し方が実際にあるのか、確かめてからにします。

## 記事の中を探す（`/apps/` の検索）

トップページの検索は、カードの `data-name` と `data-keywords` しか見ていません。
紹介記事は 32 本で **203,000 字**ありますが、その中身は検索の外にありました。
「ローマ字」「二学期」で探しても、何も出てきませんでした。

`tools/sync-updates.mjs` が `data/search-index.json` を書き出します。
**手で直しても次の実行で消えます。**

- **見出し（h2）ごとに 254 件**に切ってあります。当たった節の名前を出せて、
  `/apps/<slug>/#s-3` のように、その節へ直接つなげます。
  目次で振った id（`article-toc.mjs`）がそのまま行き先になります
- **書き出し済みのページから作ります。** GitHub を見に行かなくても作り直せるので、
  朝の組み直しが途中で失敗した日でも、索引だけが古いまま取り残されません
- 索引は 663KB（配るときに gzip がかかって 182KB）。**検索の欄に触れるまで読み込みません**。
  Service Worker の先読みにも入れていません（`SHELL_FILES` にあるのは `search.js` だけ）

> [!NOTE]
> 本文を 300 字までに切れば索引は 67KB になりますが、そうすると 7 割の文字が
> 探せなくなります。**書いてある言葉で探して「見つかりません」と出るのは、
> 検索が無いより悪い**ので、削らずに、読み込む時機のほうで軽くしています。

## 更新のフィード

`feed.xml`（Atom）を `tools/sync-updates.mjs` が書き出します。**手で直しても次の実行で消えます。**

一度アプリに辿り着いた人が、次に何が出たかを知る手段がサイトにありませんでした。
X と note は続けるかどうかが本人次第ですが、フィードは置いておけば勝手に届きます。

- 中身は**読むもの**に絞っています。紹介記事と、まだ記事の無い新しいアプリ。
  「最近手を入れたもの」は入れません。細かい push が流れ続けるだけで、
  購読している側にとっては報せる値打ちがないためです
- 新しく公開した順に **20 件**まで
- `<link rel="alternate" type="application/atom+xml">` をトップ・紹介ページ・
  記事ページの `<head>` に入れてあります。フッターにも見えるリンクを置いています
- 日付は `data/apps.json` の `YYYY-MM-DD` しか無いので、その日の始まり（日本時間）
  として書いています。時刻まで正確である必要はありません

## 動きについて

動きはすべて「操作の結果が分かる」ためのもので、0.2〜0.4 秒に収めています。

- **スクロールで現れる** … `IntersectionObserver` で、画面に入った要素を一度だけ表示します。
  隠すのは JavaScript が動いたときだけ（`<html>` に `js-reveal` が付く）なので、
  読み込みに失敗しても本文が消えることはありません。
  さらに、画面内に入っても出現待ちのままの要素があれば、監視が届いていないとみなして
  全部表示する保険を入れてあります。
- **絞り込みでカードが移動する** … 位置を測ってから差分を戻す FLIP を、
  Web Animations API（`element.animate`）で行っています。外部ライブラリは使いません。
- **動きを減らす設定** … `prefers-reduced-motion: reduce` のときは、帯を止め、出現も
  絞り込みの移動も行わず、これまでどおり瞬時に切り替わります。
- **カードの中で画面写真が切り替わる** … 画面に入っているカードだけ、約 3.4 秒ごとに
  静かに入れ替わります。マウスを乗せると 1.3 秒間隔になり、別のタブを見ているあいだは止まります。
- **指で触る画面** … `@media (hover: none)` でホバーの見た目を切り、押したときの反応だけ残します。
- **ヒーロー下の帯** … 装飾に帯域を先取りさせないため、**先頭 6 枚だけ即時**に読み、
  残り 24 枚は画面に入ってから読みます（`loading="lazy"`）。30 枚すべてを即時に読むと
  200KB ほどになり、本文のサムネイルより先に回線を使ってしまいます。
- **押した結果の知らせ** … 「リンクをコピーしました」を画面の下に 2.2 秒だけ出します。
  ページ全体で 1 つしか持ちません。「動きを減らす」設定では、動かさずに出します。

## 設計の方針

- **依存ライブラリなし。** 外部の CSS・JavaScript・Web フォント・画像を読み込みません。
  読み込みが速く、外部サービスに閲覧の記録が渡りません。
- **JavaScript が無くても読める。** 41 本のカードはすべて HTML に書いてあります。
  JavaScript は検索・絞り込み・テーマ切り替えだけを担い、無効なときはそれらを表示しません。
- **配色は明暗どちらでも AA 以上。** 本文と背景の組み合わせは、コントラスト比 4.5:1 を上回る値を
  選んでいます。OS の設定に追従し、ヘッダーのボタンで切り替えもできます。
- **誇張しない。** 説明文は、そのアプリが実際にしていることだけを書きます。
- **外へ送らない。** 共有ボタンは、押したときだけ端末の共有画面（または X の投稿画面）を開きます。
  隣の「リンクをコピー」は端末のクリップボードに写すだけです。
  「最近開いた順」に使う記録（`giga-school:recent`。多くて 8 件）も端末の中だけに残り、
  「開いた記録を消す」でいつでも消せます。アクセス解析は入れていません。
- **オフラインでも開ける。** Service Worker（`sw.js`）がトップページと画像を控えておきます。
  ページ本体は毎回ネットワークを先に見るので、内容が古いまま残りません。
  もし表示がおかしくなったら、`sw.js` の先頭にある `VERSION` の値を変えてください。
  古い控えを全部捨てて作り直します。
