# 作業開始プロンプト（短縮版・そのまま貼る用）

各アプリの練度を上げる作業を Claude Code で始めるとき、この節をそのまま貼ります。
根拠と実例つきの長い版は `standards/docs/app-hardening.md`（ポータルが手元にあるなら
必ず先に読ませること）。

---

これから `<リポジトリ名>` の `<目的>` に取り組みます。次の規律を守ってください。

**範囲**
- 1 リポジトリ・1 PR・1 目的。ついでの整理を混ぜない。付帯工事は PR 本文に「次の入口」として書くだけにする
- 着手前に `grep -rn "見送\|入れない判断\|持ちません" AUDIT.md README.md quality.config.json` を実行し、
  日付つきの人間の判断がある項目には勝手に着手しない
- 迷ったら決めない。とくに「外部から実行コードを取る例外」「学習記録の設計変更」
  「AI が児童へ直接届く経路」は必ず私に確認する

**着手前に必ず**
```bash
git fetch origin
DEF=$(git symbolic-ref --short refs/remotes/origin/HEAD)
git log --oneline $DEF..HEAD && git diff HEAD $DEF --stat
git switch -C claude/<この作業だけの名前>-$(date +%m%d) $DEF
```
- 手元のブランチをそのまま使わない。43 本中 36 本が「マージ済みなのに未マージに見える」
  ゾンビブランチの上に立っている。その上に積むと PR の差分に既存の変更が再び現れ、
  `mergeable_state` が dirty になって **CI が失敗ではなく 1 件もスケジュールされない**
- `npm run` のスクリプト名を推測しない。`package.json` と `.github/workflows/` の両方を読む
  （self-test は `check:self-test` / `check:self` / `verify-gate` / `gate:selftest` などバラバラ、
  package.json に無く ci.yml が直接呼んでいる repo もある）

**「緑」を信じない**
- 出力に「走っていません」「未取得」「dist が無い」が 1 行でもあったら合格として報告しない
- ビルド成果物を見る検査は **`npm run build && npm run check` の順**で回す
- self-test は「0 件」ではなく「作業前から増えていない」で判定する。
  もともと落ちている分は直さず PR 本文に列挙する
- `check-drift.mjs` は対象リポジトリ直下で実行し、`✅ 正本と一致しています（N ファイル）` の
  **N まで読む**。「持ちません」は緑ではない
- 正本と一致しているのは 18 本中 9 本だけ。残りは同じパスに置かれた別物で、
  SW 版検査などが存在しない。**フォーク側の検査ロジックには触らない**

**必ず同じ PR に入れる**
- 配信物を 1 バイトでも変えたら **SW の版**（`grep -rn "__APP_VERSION__"` が空なら手書き。
  定数名は `sw-build.config.json` の `versionConst` で決まり `APP_VERSION` とは限らない）
- `appId` を変えたら 4 か所すべて
- `.gs` の公開関数（末尾 `_` 無し）を新設したら認可。`google.script.run` は
  トップレベル関数を誰でも呼べるので、1 つの抜けで境界が破れる
- Chrome 拡張を触ったら `manifest.json` の `version`。上げないと 1 台にも配られない

**反映経路を確定してから「直りました」と言う**
`CNAME`→Pages / `.clasp.json`→GAS 自動デプロイ / 拡張の `manifest.json`→ストア審査 /
`netlify.toml`→Netlify。**マージ＝反映ではない経路がある**

**この環境の制約（できないことを「確認しました」と書かない）**
- `gh` は無い。CI は `mcp__github__actions_list` で見る
- 外部通信は塞がれている。本番疎通が要る検査は走らせられないので、
  手元で目視確認し PR 本文に「本番疎通は未確認」と明記する
- ブラウザ実測はできない。見た目・性能は「未計測」と書く。確認手段が無いのに見た目を変えない

**報告**
- 実行したコマンドと出力で語る。「〜のはず」を書かない
- 直せなかったもの・見送ったものを必ず書く
- 私は 1 人で 43 本を保守している。次に何をすればよいかが 1 行でわかるように書く
