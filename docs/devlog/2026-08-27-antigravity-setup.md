## 何をしようとしたか

普段は GitHub と Claude Code を使って、33 本ある GIGA スクール向け Web アプリの開発やサイトの管理をしています。

今回、Google の Antigravity を導入することにしました。これまで通り Claude Code を主軸にしながら、ブラウザの自動操作や実機検証など、Antigravity にしかできない強みを組み合わせて作業を快適にしたかったためです。

ところが、最初に IDE を開いた段階で、設定ファイルがどこに何のために置かれているのかが分かりませんでした。共通ルールを指定するファイルと、システム側で読み込まれる設定が重複しており、無駄な指示が重なっている状態でした。

さらに、手元の環境には .antigravity だけでなく、身に覚えのない .gemini というフォルダも生成されていました。これを勝手に整理したり消したりしてよいのかも判断がつきませんでした。

Claude Code の資産を壊さずに、Antigravity の特化設定を整えて、既存アプリのブラウザ自動検証までを通すことにしました。

## 出したプロンプト

現状を整理するために、はじめに出したのはこれです。まっさらな状態から出しました。

```
私がAntigravityを快適に最大限活用できるようにしたい。どのような設定が必要か教えてください。スキルやエージェント、MCPなどにも興味がありますが、詳しいことは何も知りません。
```

これで全体像の説明が返ってきましたが、一度にすべてを設定しようとすると混乱します。そこで進め方を絞りました。

```
STEP1から順番に現状の把握と、納得行く形での最適化・完成を目指したい。
```

順番に進めることを指定したプロンプトです。これで全体共通の基盤からプロジェクト個別の設定へと、段階を踏んで整理できるようになりました。

設定を整えたあと、実機の検証を試すときに出したのがこれです。

```
既存のWebアプリのブラウザ自動検証をAntigravityで実行してみる
```

これだけで、候補として提示された 4 つのアプリの中からリバーシを選び、ローカルサーバーの起動からブラウザサブエージェントによる盤面操作、駒の反転判定、動画の記録までが一通り自動で走りました。

## うまくいかなかったこと

設定の整理で最初につまずいたのは、ルールの重複でした。

IDE 直下の設定ファイルに「日本語で返答する」「コード内のコメントも日本語で記述する」という 3 行の指示を書いていました。ところが、システム側のグローバル設定ですでに日本語の応答が強制されていました。同じ指示が 2 重に読み込まれており、無駄にトークンを消費していた形です。

エディタ側の設定ファイルは、言語の指定を外しました。Windows や PowerShell で文字化けを起こさないための文字コード指定と、プロジェクトごとのファイル配置方針だけに書き直しています。

もうひとつの失敗は、.gemini という見慣れないフォルダを、不要な一時フォルダだと思い込んで削除や移動をしようとしたことです。

.gemini は Antigravity の AI 思考エンジン本体やログ、認証情報を保持するシステムの基盤領域でした。ここを不用意にいじると、AI そのものが起動しなくなります。エディタ側の .antigravity と、AI 本体の .gemini は、完全に役割が分かれていることを確認して手を出さない判断をしました。

さらに、検証用のローカル Web サーバーの起動でも止まりました。

コマンドで Python の簡易サーバーを立ち上げようとしました。

```
python -m http.server 8085
```

私の環境では Python の実行パスが通っておらず、終了コード 1 で失敗しました。環境に依存するコマンドをそのまま打ったのが原因です。

インストール済みの Node.js を使った 30 行ほどの小さな配信スクリプトを書き、バックグラウンドの常駐タスクとして起動させることで解決しました。

## 新しく知ったこと

Antigravity では、ワークスペース直下に .agents というフォルダを作ることで、プロジェクト専用のルールとスキルを配備できます。

Claude Code が使う .claude フォルダと干渉しないため、両方のエージェントを同じリポジトリで同時に使えます。リポジトリ内の standards 配下にある共通スキルをそのままコピーして配備するだけで、Antigravity 側でも開発記録や紹介記事の生成スキルが動くようになりました。

また、ブラウザサブエージェントを実行すると、操作ログだけでなく操作画面全体の WebP 動画が自動で保存されます。手動で画面キャプチャを撮らなくても、動作確認の証拠がそのまま手に入ります。

これまで手作業で行っていた「ローカルでサーバーを立てる」「ブラウザを開いて手動で何手か打つ」「スクリーンショットを撮る」という一連の確認作業が、指示 1 つで自動化できることが分かりました。

## できあがったもの

ワークスペース直下に .agents フォルダを配備し、GIGA スクールアプリの開発基準を定めたルールと、2 本の記事作成スキルを配置しました。

リバーシのアプリに対してブラウザ自動検証を実行し、8x8 の盤面描画、駒の着手と反転、待った機能の動作を確認した記録動画を生成しました。

初期盤面の黒 2 枚・白 2 枚の状態から、初手で 4 対 1、2 手目で 3 対 5 と正しく反転し、スコアが更新される様子を動画として残せました。

## 次に同じことをする人へ

- 言語設定などの基本ルールはグローバルに任せ、IDE の設定ファイルには OS やシェル固有の文字コードを置く
- .gemini フォルダはシステム本体の領域なので、削除や移動をせずそのまま保持する
- 複数の AI エージェントを併用するときは、共通の正本フォルダからそれぞれのエージェント用フォルダへ配備する
- ローカルのテスト用サーバーは、環境の差が出にくい Node.js のスクリプトで立ち上げる
- ブラウザの自動検証機能を使うと、操作の証拠となる WebP 動画が自動で残る
